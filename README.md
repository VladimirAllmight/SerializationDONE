**1) Создать структуру классов Student, Subject, Class.
2) Создать экземпляры объектов и сохранить в файле, так чтобы потом можно было их воссоздать, используя стандартный механизм сериализации Java
3) Прочитать экземпляры из файла и восстановить объекты**

Основной класс - Main, внутри него создана package-private структура классов Student, Subject, Class.Класс Student содержит два поля: name (строковый тип) для хранения имени студента и subjects (тип LinkedList, содержащий объекты Subject) для хранения списка предметов студента. Класс Subject включает два поля: subjectName (строковый тип) для названия предмета и score (тип byte) для оценки по предмету. Класс Class описывает учебный класс и содержит три поля: roomNumber (строковый тип) для номера кабинета, students (тип List с объектами Student) для хранения списка студентов и subjects (тип List с объектами Subject) для хранения списка предметов.

Все классы реализуют интерфейс Serializable, что позволяет использовать стандартный механизм сериализации Java. Для обеспечения совместимости версий классов добавлено поле serialVersionUID, уникально идентифицирующее версию класса. Это предотвращает ошибки при десериализации объектов в случае изменений структуры классов. Если это поле не указывать, Java будет генерировать его автоматически на основе структуры класса, что может привести к несоответствию версий при изменении кода.

В теле класса Main реализуется следующий функционал: создание экземпляров классов Subject, Student и Class, сериализация их в файл objects.ser и последующая десериализация из этого файла. Программа демонстрирует создание двух объектов Subject (например, "Mathematics" с оценкой 90 и "Science" с оценкой 85), одного объекта Student с именем "Ivan" и списком предметов, а также объекта Class с номером кабинета "101", списком студентов и списком предметов. Для сериализации объектов используется ObjectOutputStream, а для десериализации — ObjectInputStream.

**4) Разработать XSD схемы с описанием этих типов и при помощи библиотеки Apache XML Beans сгенерировать Java-классы на основе XSD.
5) Создать экземпляры XML объектов (заполнив значения свойств) и сохранить их в файлы.
6) Прочитать экземпляры XML объектов из файлов. 
**
XSD схема с описанием классов располагается в директории /xsd. Элемент Subject представлен типом SubjectType, включающим два поля: subjectName, предназначенное для хранения названия предмета, и score, которое хранит числовое значение типа byte. Элемент Student описывается типом StudentType и включает в себя имя студента (name) и список предметов (subjects), где каждый элемент списка имеет тип SubjectType. Для определения списка предметов используется вложенный анонимный сложный тип, позволяющий указать, что элемент Subject может повторяться произвольное количество раз. Элемент Class описывается типом ClassType, который содержит номер кабинета (roomNumber), список студентов (students) и список предметов (subjects). Для каждого списка используется вложенный сложный тип с возможностью хранения множества объектов, где элементы Student и Subject повторяются неограниченное количество раз. Все элементы (Subject, Student, Class) объявлены глобально.
Генерация java классов происходит при помощи Apache XMLBeans. С подключением возникло много проблем, но об этом написано ниже. Экземпляры сгенерированных классов определяются в классе Instances: сначала создается объект ClassDocument, который соответствует корневому элементу XML. В этот объект добавляются элементы, такие как номер класса, студенты с их именами и предметами с оценками. Далее создается строка XML с помощью StringWriter и сохраняется с опцией форматирования для удобного чтения. После этого строка XML парсится обратно в объект с использованием StringReader и метода Factory.parse(), восстанавливая все данные в исходную структуру. В конце выводится информация о классе, студентах и предметах, которые были восстановлены из XML.

В ходе работы я познакомился с системами сборки Maven и Gradle. Из 3 веток проекта (Gradle с генерацией через плагин, Gradle с генерацией через написание "таски" на генерацию и Maven) полностью рабочим оказался только первый вариант. Во втором случае не получилось избавиться от циклической зависимости с задачами компиляции Java. Генерация классов из XSD (в работающем варианте) с помощью плагина com.liferay.xsd.builder в Gradle происходит следующим образом: плагин подключается через зависимость в buildscript, после чего активируется с помощью apply(plugin = "com.liferay.xsd.builder"). Плагин анализирует XSD-схему и автоматически генерирует Java-классы, которые соответствуют описанным типам данных, таким как комплексные (<xs:complexType>) и простые (<xs:simpleType>) типы. 

Для запуска сборки проекта в терминале следует написать:
_./gradlew.bat build_
Для запуска класса с первой частью задания:
_./gradlew.bat runClassOne_
Для запуска второй части задания
_./gradlew.bat runClassTwo_
Для запуска двух классов сразу
_./gradlew.bat runBothClasses_
